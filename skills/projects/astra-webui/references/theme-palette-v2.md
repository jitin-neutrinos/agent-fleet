# Theme palette v2 (OKLCH) — how the palette works and how to change it

State: shipped 2026-10-05 as commit 92f4724 (+1bbc06c for the derivation script). Computed in OKLCH, brand blue retained, WCAG-enforced.

## The four places the default palette lives (must move together)

1. `src/index.css` — `@theme` dark token literals, `[data-theme="light"]` token block, and the generated channel table (`--c-N` / `--light-c-N` triples + `--r-c-N` role annotations, 171 dark + 124 light).
2. `scripts/theme/build-palette.mjs` — the `ASTRA_UI` object (comment says "must equal current index.css values").
3. `src/theme-engine/palettes.json` — GENERATED by build-palette.mjs + a11y-pass.mjs. Never hand-edit; verify astra-ui entry matches after regeneration.
4. `index.html` — theme-color metas (dark literal + light media variant + pre-paint light branch in the inline script).

Derivation source of truth: `scripts/theme/compute-palette.mjs` — OKLCH with gamut mapping and a WCAG fit loop; writes `scratch/palette-latest.json`. Run it first, then apply the values.

## Rewriting the channel table

- Rewrite only ANNOTATED channels: parse `--r-light-c-N` / `--r-c-N` role tags, map role → palette slot (the accent role stores under the legacy key `--color-cyanx`), replace the channel triple. Unannotated `--c-N` are deliberate theme-stable literals.
- The static light slate ramp in index.css must match the runtime derivation in theme-store.syncThemeColorMeta (light keep%: 300:68, 400:55, 500:45, 600:40, 700:30).

## Where old-literal residue hides

- Tailwind **arbitrary-value utilities in TSX**: `bg-[rgba(34,211,238,0.1)]` etc. bypass the role system. Convert to role classes (`bg-accent/10`, `ring-accent/30`) or `color-mix(...var(--color-accent)...)`. grep `rgba\(34, ?211, ?238|22d3ee` across src.
- `var(--token, #fallback)` fallback literals (graph-view, native-charts, theme-store accent fallback, skeleton shimmer fallbacks).
- Dead Tailwind rules from committed build artifacts (android/, .audit-evidence/, scratch/ bundles get content-scanned): re-emit old arbitrary utilities as UNUSED selectors. Verify a residue is dead (no DOM element carries the class) before worrying.
- `#f8fafc`-style whites on accent/red FILLED buttons are intentional forever-white in both modes — do not re-point them at brandtext.

## Contrast gates (measured vs void, WCAG relative luminance)

- Dark: brandtext ≥7 (AAA), muted ≥4.5, accents ≥3. Light: accents ≥4.5, muted ≥4.5.
- Light slate-ramp worst case = ink 55% over void must be ≥4.5 — the shipped pre-v2 palette measured 3.87 there. Deeper ink is the only lever (a11y-pass auto-deepens for generated palettes).
- Skeleton greys: pinned literals in `skeleton-grey.check.ts` AND first-paint literals in index.css AND derived at runtime by `neutralGrey()` — update all three; the check recomputes the derivation, so values must match its formula.

`scripts/theme/parity/run.mjs --dist dist --out <dir>` captures 40 rendered states as computed-style JSON. Grep the JSON `c` fields for old/new hexes as painted-pixel evidence.

## Retinting chat bubbles (the five-var, two-scope rule)

The chat bubble skin is driven by CSS vars, not Tailwind. There are FIVE of them, all in `src/index.css`:

- AI / assistant: `--bubble-ai-bg`, `--bubble-ai-border`, `--bubble-ai-code-bg`, `--bubble-ai-inline-bg` — consumed by `.chat-turn` and `.chat-bubble-ai`.
- User: `--bubble-user-bg`, `--bubble-user-border`, `--bubble-user-text` — consumed by `.chat-bubble-user`; `.chat-user-chip` (header icon) also reads `--bubble-user-text` for its colour.

Rules that bite if forgotten:

1. **Two scopes, not one.** Every one of those tokens is declared in `:root` AND re-declared under `[data-theme="light"]` further down the same file. Patching only `:root` leaves light mode painting the previous tint while dark mode updates — reads as a half-applied change. Patch both.
2. **Keep AI and user on different channels.** The user bubble is NEUTRAL GRAY (`rgb(var(--c-110))` in dark, `color-mix(in srgb, #1a1a1f 8%, #ffffff 92%)` in light); the AI bubble carries the visible accent wash (`--color-accent` ~22% oklab dark, ~24% srgb mixed into `#ffffff` light). Never point the user bubble back at `--color-emerald` — that was the pre-2026-10-07 state and the owner had it replaced.
3. **Light-mode tints mix toward the paper, not toward transparent.** With a chat backdrop set, a transparent bubble lets dark media show straight through and light ink sits on it unreadable. Always keep a `#ffffff` (light) or near-void (dark) portion in the mix; accent % controls how strong the wash reads, paper % controls legibility.
4. **The user-bubble glow is hardcoded to its channel.** When swapping the user bubble off a coloured channel, rewrite the `box-shadow` on `.chat-bubble-user` (around line 1518) — a stale emerald glow around a gray bubble reads as a bug.
5. **Verify against the SERVED bundle.** `npm run build` == deploy, then grep `dist/assets/index-*.css` for the new percentages (e.g. `color-mix(in oklab, var(--color-accent) 22%`). Source-level greps prove nothing once lightningcss has rewritten the file.

## v2 palette facts

- Dark: void #090c12 / midnight #11151d / depth #1a1f29 / surface #252b39 / brandtext #f2f3f7 / muted #8d929e / accent #2bc8f3 (hue 222.1, chroma 0.135 — was #22d3ee hue 211.5, so the blue family is retained) / violetx #8f9eef (was a duplicate of emerald) / fuchsiax #dc6dd4 / redx #ef6661 / emerald #49cc95 / amber #e6b14e.
- Light: cool near-white paper #f3f6fb (was warm cream), ink #040408, accent #015ba6 (readable saturated blue, replaces muddy dark cyan #0369a1).
- Surfaces are hue-tinted navy (264° world) instead of violet-cast grey — the 2025-26 premium-dark convention.
- Elemental palettes (Fire/Water/Earth/Wind) re-derived 2026-10-05 (commits 13b82b8 + e0fa1c8) via `scripts/theme/compute-elemental.mjs`: Fire ember 35° on warm charcoal, Water aqua-teal 176°, Wind spring green 132°, Earth gold 85° — accent separation ≥44° from Astra blue (222°) and from each other, asserted. Owner rule: NO blue (hue 195–300 at C>0.02) anywhere in Water or Wind — the script asserts every role in both modes. Elementals are RUNTIME palettes: only build-palette.mjs ELEMENTAL + regenerated palettes.json change; index.css is untouched by non-default palettes.
- Light-mode warm papers: chroma (not ink depth) is the slate-ramp lever — warm paper C must stay ≤0.007 or ink@55%-over-void cannot reach 4.5:1 even with near-black ink (warm hues carry more luminance per byte). Keep light void L≈0.968 across themes.
- Tone colours are SEMANTIC, not one-accent: callout dot/title, terminal info/stderr, badges, checklist done/fail glyphs, step markers, compare pro/con, kpi up/down deltas, timeline dots → accent/emerald/amber/redx theme roles; chart series = 5 distinct hues (accent/emerald/amber/fuchsiax/redx). The older 'one accent everywhere' owner rule was superseded — but law 3 (NO coloured edge rails, pinned by canvas-theme.check.ts) still stands: tone rides dots/glyphs/chips/fills, never left borders.
