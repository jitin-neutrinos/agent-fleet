# Button-bar design system: fill conventions, selected states, flat surfaces

Owner mandate family (2026-10-05): composer bar buttons, sidebar selected states and badges all speak ONE visual language. Reading these rules BEFORE restyling any control avoids a second "make it flat / make it consistent" round.

## The one visual grammar

- **Left bar buttons (options / effort / attach / yolo) and send match each other:** 34×34, border-radius 10px, solid `var(--color-accent)` fill, contrast glyph (void ink dark / `#f8fafc` light), one neutral elevation shadow layer (`0 1px 2px rgba(0,0,0,.25)` dark, `none` light). No gradient, no ring, no glow, no `filter:` — state signaling is background-color only (hover = lighter solid, open = darker solid).
- **NO outline when there is fill; NO fill when outline.** Owner correction history: first "fill", then "remove the outline now that we have fill". The single exception: **yolo OFF (disabled) keeps both a 45%-accent container outline AND the bolt glyph outline-only (transparent fill, accent stroke)** — enabling yolo removes the outline and fills the container with the ink bolt. Both states sit in ONE component chain (`.chat-chip-yolo` + `.chat-chip-on`), so never write the TSX `fill=` attribute on that glyph — CSS state classes own it.
- **Icons are stroke-only (`fill:none`) on filled containers** unless the glyph's silhouette is the point (the yolo bolt on OFF, filled accent). A `fill="currentColor"` TSX attribute beats CSS `fill:none` (attribute > stylesheet rule), so removing the attribute is part of the change, not optional cleanup.
- **Filled selected state is universal** (sidebar nav item, collapsed rail, chats-panel active row, Work group header): full accent container + ink label + ink glyph, `text-void` accent. NOT a 10% accent tint — the owner rejected tint-based selection. Selected mechanism class: `.ast-nav-selected`. The collapsed rail is addressable via `.ast-rail` on the sidebar root (added when collapsed) — style both states or a collapsed rail silently keeps the old style.
- **Badges follow the same system** (`.ast-unread-badge`, rail + mobile variants): translucent accent fill, accent text, hairline border. They anchor differently per layout state; anchors sized for `99+`, not typical values.

## Pitfalls that actually bite

- **Specificity wars: a later rule at equal specificity silently defeats your new state.** A legacy `.chat-chip-icon.chat-chip-on` tint rule later in the file turned yolo-ON into a 14% tint with a void-ink glyph = INVISIBLE icon in dark mode ("yolo is broken in dark mode"). Fix by writing the state selector one class richer (`.composer-bar-card .chat-chip.chat-chip-yolo.chat-chip-on`, 4+ classes) rather than fighting source order. Grep the cascade for sibling rules on the same selector before assuming your rule applies.
- **Icon disappearing on an open/filled control = ink-on-ink.** Legacy `chat-chip[aria-expanded=true] .cmenu-trigger-ico { color: accent }` recoloured the glyph to the same accent as the new filled background. Preserve contrast on open state by re-declaring the glyph colour under the new-state selector; the [aria-expanded] ink swap rules exist to be overridden.
- **Measure, don't trust the source:** the working tree can carry an UNCOMMITTED fix; the served bundle can predate it. After building, grep the served `dist/assets/index-*.css`/`js` for the new declaration. And change the TSX className lists too — Tailwind glow utilities (`shadow-[0_0_16px_rgba(34,211,238,0.12)]`, `hover:shadow-[…]`) inline on the JSX live OUTSIDE any CSS rewrite and reproduce a glow the CSS audit already removed. Audit className strings along with the stylesheet.
- **When flattening, flatten ALL layers per button:** background gradient→solid, every extra `box-shadow` glow layer→the one elevation layer (dark) or none (light), `filter:brightness()` hovers→solid `color-mix` background hovers (a transition list keyed on `filter` needs updating to `background-color` too, or hover snaps).
- **The composer bar's measurement probe mirrors real chips** (`.chat-bar-probe` spans share `.chat-chip-icon` under `.composer-bar-card`), so a restyle leaks into hidden measurement copies — benign for width but confusing in captures; neutralise with a probe-scoped override (`background:transparent!important` etc.) so the probe stays a pure geometry copy.
- **Reorder = place + priority are independent.** Visible bar order is the JSX/children order inside the flex row (options → attach → effort → yolo). What collapses into the overflow menu first is governed by `COLLAPSE_ORDER` in `src/lib/overflow-fit.ts`; don't touch the fit logic to change visible order, and don't expect the fit tests to encode visual order.
- **Light twins are not optional.** Every dark rule in the system needs `[data-theme="light"]` counterpart before deploy; the light palette var is `rgb(var(--light-c-1))` for accent fill and `rgb(var(--light-c-34))`/`#f8fafc` for ink-on-accent. Compare computed styles in BOTH themes (localStorage `astra-theme` = `light`/`dark`, reloaded), not assumed symmetry.
- **Owner answer pattern for repeated visual tuning:** after the second rejected take on an aesthetic knob, ship best-current and offer named options with one line each; after a `flat red` / `flat accent` steer, the matching hover variant must also drop its glow ("flat red but hover slightly whitened" was accepted), not only the resting state.
