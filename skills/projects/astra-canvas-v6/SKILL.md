# Astra canvas v6 (shipped 2026-10-04)

## Mobile geometry (2026-10-05) — measure, don't read the CSS

`scripts/mobile-canvas-audit.mjs` + `src/lib/probe-canvas-mobile.probe.tsx`: 63
block fixtures × 360/390/412 × dark+light = 378 measurements in a real Chromium,
through the real card and the real stylesheet. Run it before touching a canvas
layout and again after. The findings that were NOT visible in the source:

- **`grid-area: <name>` with no `grid-template-areas` on the container collapses the cell to the row-gap width.** Proved in isolation: three variants of one file, `grid-area: a` → grid resolves `288px 0px 11.5px` and cells 12px; no `grid-area` → one 300px track, two 300px cells. LayoutView emitted the area name for EVERY mode but only `.mg-N` (bento) declares the template, so stack/split/grid painted their children 9× too narrow (KPI cells at 30px, labels hard-clipped). **Emit the area name for bento only.** On phones the bento override must ALSO force `grid-area: auto !important` on the cell — `!important` is the only thing that beats LayoutView's inline style, and without it the container fix just moves the defect one level down.
- **The biggest sub-11px block was chart axis chrome** (468 tspans at 10px). recharts `tick` / nivo `theme.text.fontSize` / a shape's `fontSize` are JS props and cannot inherit a CSS floor — the floor has to be stated where it is read. And raising the font without decimating makes it worse: recharts 2.15's `interval` is an integer SKIP (`AxisInterval = number | 'preserveStart' | …`, there is NO separate `intervalMode`), so derive a count — one drawn label per ~78px of plot. Phone plots are SHORTER (sankey 300→220), not taller: a 451px card is most of the screen.
- **Four harness faults that manufacture a green baseline** — fix these before believing any number: build with the app's own `vite.config.ts` or `@theme`/`--font-sans` never resolves and every glyph measures as Times 16px; force `.chat-turn { content-visibility: visible }` or off-screen turns measure 0×0 and every chart reports "painted nothing"; pass thresholds as ONE options object (an array argument destructured as three parameters left `MIN_TAP` undefined, so every `height < NaN` was false and the audit reported ZERO tap defects on a page full of 14px controls); and exclude an element's OWN scrollWidth, SVG children (no layout box) and zero-width wrapper divs. Also: katex emits U+200B at 1px in its MathML twin — 54 "sub-11px" findings were that one invisible character.
- **`git add -A` sweeps another session's staged work into your commit.** The harness commit picked up an unrelated `color-chip.ts` because a concurrent session had already staged it. Stage explicit paths, or use `git apply --cached` on the individual hunks when one file holds several unrelated fixes (`src/index.css` did).

See the gotchas below; counts and commits are the pins.

Chart-render pins (2026-10-04, commits d322d2d / 940b7f8 / 0147e8e): native charts self-size OUTSIDE the fixed-height container with an explicit plot height; recharts legends replaced by an in-flow `ChartLegend` AFTER the plot (never re-introduce recharts `<Legend>`, it is absolutely positioned inside the surface); scatter accepts pairs/objects; `src/lib/etiquette.check.ts` (RG-078) + `scratch/canvas-v6/etiquette-e2e.mjs` (4 widths, 40 assertions) pin the text-etiquette law (wrap by word, no ellipsis on prose, no widows, KPI chips fit-content + flex-wrap).

## Hard-won gotchas

- **dagre self-loops are broken at the source** (draw outside the canvas / through the node). `routeSelfLoops` replaces them with a one-side detour; keep `clearLabelBoxes` (chips slide off foreign corridors).
- **dagre margins can under-estimate extreme routes**: on overhang, re-layout once with margin doubled (two-pass, up to 4). Never clamp points inside nodes.
- **SVG `<text>` multi-line via tspan**: line 1 `y` must be the TOP baseline, not a block-centre (a centre y pushed detail lines out of their node box).
- **`getBoundingClientRect` is UNCLIPPED**: when asserting 'no overlays over a scroll viewport', clip boxes to the wrapper first, and measure BUTTONS, not their full-width row container.
- **Escape on a selection must be a capture-phase window listener** — focus can live outside the diagram subtree after a panel-neighbour click.
- **`fs.cpSync` on a SYMLINKED fixture dir is flaky** across runs — test fixtures must be real directories.
- **Two agents in one repo can corrupt a shared file's seam during their own merges** (regression-gate lost its spawnSync block). After a concurrent-session commit, re-run the full suite before trusting the tree; repair from the last known-good commit and re-pin missing rows.
- **Harness-block recipes must be compressed, not truncated** (M4 sync): the verbatim RECIPES render = 2,893 chars > the 2,400 harness budget; `compressRecipe()` strips the `(…)` glosses (arrow names + order intact, 2,358 chars) and ONE copy ships as the generator body (`compressRecipe` regex, `MAX_HARNESS_BLOCK`) — verbatim bodies stay in the SOUL block and the sync doc; a compression is a rendering decision, never a rewrite.
- **`search_files` returns 0 hits inside hidden dirs — use `grep -rln` for fake-home work** (M4 session 20261004_132837_56ae1d): `search_files(pattern="astra-canvas:start", path=".../wt-fleet/fake-home")` → `total_count: 0` although `.claude/CLAUDE.md`, `.gemini/GEMINI.md`, `.config/opencode/AGENTS.md`, `AGENTS.md` and `.hermes/SOUL.md` all contain it — the tool skips dot-directories, and a fake HOME is nothing BUT dot-directories. Reproduced twice in that session; re-confirmed on the shipped generator 2026-10-05. A 0-result search is therefore NOT evidence of absence here; fall back to `grep -rln '<pattern>' .` from inside the tree before concluding "no markers".
- **The rendered surfaces hard-code the doc path but NO assert pins it** (same session): `canvas-surface-sync.mjs` emits `~/Work/projects/astra-webui/docs/canvas-directive.md` twice (harness block + soul block) and the check file mentions it ZERO times. Move or rename that doc and all 22 assertions still pass green while every harness rulebook and SOUL.md points at a dead path. If you move it, grep the generator for the literal, update both sites, and add the path to the check — the generator will not tell you.
- **Retention assertions must force real churn**: 'keep 20' can't be probed by 22 plain reruns (they change nothing, so they create no run dirs) — revert one file's bytes to pristine before each run so it re-drifts, then assert exactly 20 dirs remain; and with second-granularity run-dir timestamps you need a zero-padded collision suffix (`-002`) plus mtime-first sort or same-second runs squeeze to ONE dir. Special-case run 0: in a FRESH fixture copy the first write changes EVERY target (61), and only the later reverted-file runs change 1 — an unconditional `/^canvas surfaces: 1 changed/` assert fails on iteration one.
- **`--check` must mirror write exactly**: a target skipped in write mode (parent dir missing, `~/AGENTS.md` absent) is skipped too in check mode — never counted as drift, or the write→check round-trip can never go exit 0. `--check` itself never writes and never backs up, so the backup-retention path has to be exercised separately.
- **Fake-home runs need an explicit `--schema`, and the target-walk has a creation policy**: `--schema` defaults to `<home>/Work/projects/astra-webui/src/lib/canvas-schema.ts` — i.e. derived from `--home` — so any run against a throw-away home that omits `--schema` exits 2 (`schema not found`) before touching a file. On the write side, a harness rulebook whose PARENT dir exists is CREATED when the file is absent; only `~/AGENTS.md` is never created (skip `file missing`). And a `return void add(...)` inside the target loop returns from the whole function — it silently drops every remaining target while the tool still exits 0; `continue` instead.
- **Fixture trailing-newline states are mixed** (M4 sync): `CLAUDE.md` / `GEMINI.md` / opencode `AGENTS.md` end with NO newline after the end marker, `~/AGENTS.md` and `SOUL.md` end with `\n`, and one `SKILL.md` ends with no newline at all. The append path must therefore trim trailing whitespace and always terminate, and the "byte-identical above the marker" assert may allow exactly that one normalisation (`orig.replace(/\s+$/,"") + "\n\n"`) — nothing more.
- **The real SOUL.md's canvas section runs to EOF**, so the "everything after the next `## ` heading is byte-identical" assert is VACUOUS as written (`orig.indexOf("\n## ", at+1)` is `-1` → `suffix` becomes the whole original). Append a `\n## Later section\n\nuntouched body text\n` to the fixture copy FIRST, then assert `now.startsWith(prefix + marker)` and `now.endsWith(suffix)` — and remember the new prefix is `orig prefix + the marker line`, so compare against `prefix + "<!-- astra-canvas:soul:start -->\n"`, never against `prefix` alone (that mismatch reads as "the migration corrupted the file"). The migration replaces heading→next-`## `-or-EOF in one slice, which is what keeps the outside byte-identical on a second run (markers exist → plain between-markers replace).
- **The backup run dir must be created before the first `copyFileSync`** (M4 session 20261004_132837_56ae1d): the write path computes the stamp, then copies each changed file's ORIGINAL bytes into `<home>/.hermes/backups/canvas-sync/<stamp>/`. Skipping `fs.mkdirSync(run, { recursive: true })` there makes every backup throw on the first target — and the write itself still appears to succeed because the throw only happens on the copy, so backups silently never exist. Assert the backup bytes (`7a-backup-holds-the-original-bytes`) and the retention count (`7c`) rather than trusting the write's exit 0.
- **Three authoring traps in the assert-based check harness, all of which kill the whole suite before any assertion runs** (same session): (1) a leftover half-written helper — a dead `inSet(src, constName, extra)` whose nested `${[...body.matchAll(/"([^"]+)"/g)].map(...)}` sits inside an already-templated string — fails the whole module with `SyntaxError: Missing } in template expression`, i.e. an error that names no real defect; delete dead code, don't leave it commented or half-rewritten. (2) A `const home6 = () => …` arrow declared at the BOTTOM of the try block is a TDZ landmine: any earlier step calling `home6()` throws `ReferenceError: Cannot access 'home6' before initialization` after ~14 steps have already printed `ok …`. Declare helpers with the other helpers at the top. (3) Counting DRIFT lines with `stdout.trim().split("\n").length` also counts the trailing summary line (`canvas surfaces: 61 drift (61 targets)`) → 62 vs the expected 61. Filter `l.startsWith("DRIFT ")` before counting.
- **Check-file asserts pin the exact rendered literals**: the table separator line is 4 columns (`|---|---|---|`) — an `Array.indexOf` against 3 groups misses it (substring matches don't apply to arrays); YAML `name:` values need quote-stripping (one real file even carries a trailing `\r`), and table `when`/`shape` cells escape inner `|` as `\|` before the row count is pinned.
