- **agy leaves its dev servers running** on ports 3000/3004 despite "cleaned up" claims — check `ss -tlnp` after each run and clear (or route around) before the next phase.
- The plan agent's file writes are URL-scanned: a literal link-local/metadata IP in content is refused (`Blocked: URL targets a cloud metadata endpoint`) — use CIDR wording instead.
- Check `df -h /home` before large tests — the media sandbox shares `/home` (≈100 GB free at project start).
- **User-facing API errors must never use 5xx.** cloudflared substitutes its own `error code: 502` page for ANY origin 5xx body — the UI then fails JSON parsing (`Unexpected token '<', "<!DOCTYPE "`). Engine refusals → 422; validation 400; auth 401/403. Debug split: identical request against `http://127.0.0.1:<port>` (pass an explicit `Cookie:` header — domain-bound cookies don't follow you to 127.0.0.1) vs the public URL; different bodies = tunnel mangling, same = app-side.
- **worker.ts runs outside the Next build** (node --experimental-strip-types). After any `lib/` refactor, confirm the worker still boots — a renamed/removed export leaves it crash-looping (5s respawn, "does not provide an export named …") while `npm run build` stays green. Check `server.log` for the respawn loop after every deploy.
- **`next start` renames argv to `next-server (vX)`** — pkill-by-name misses stale servers. Kill by `/proc/<pid>/cwd` match, then require exactly ONE listener (`ss -tlnp | grep <port>`) before declaring a restart clean. Stale server + freshly rebuilt `.next` = mixed-version flakiness.
